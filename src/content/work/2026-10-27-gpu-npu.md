## GPU

### shared memory broadcast 경고 = OOM 아님

- `No available shared memory broadcast block found in 60 seconds` -&gt; 워커가 결과를 안 보낸다는 뜻 (hang)
- 300초(`VLLM_EXECUTE_MODEL_TIMEOUT_SECONDS`) 뒤 `sample_tokens timed out` -&gt; `EngineDeadError`
- OOM 이면 Traceback 이 남거나 프로세스가 죽음. 이번엔 워커가 살아서 SIGKILL 까지 감

### 엔진이 죽어도 컨테이너는 Up (재시작정책 미적용)

- 엔트리포인트가 vLLM 은 백그라운드, uvicorn 은 포그라운드 -&gt; uvicorn 만 살아 있으면 컨테이너 유지
- nginx `least_conn` + 헬스체크 없음 -&gt; 죽은 서버가 500 을 빨리 돌려주니 오히려 요청이 몰림
- 수정: 두 PID 를 `kill -0` 으로 감시, 하나라도 죽으면 exit 1 -&gt; `restart: always` 로 복구
- PID 1 인 sh 는 신호를 안 넘김 -&gt; `trap` 으로 SIGTERM 처리

### 검증

- 워커에 `SIGSTOP` -&gt; 장애와 같은 hang 재현. 타임아웃 60초로 줄여서 시험

- 결과: 엔진 사망 -&gt; 5초 뒤 컨테이너 내림 -&gt; 약 1분 뒤 복구

- TP=1 이면 `--distributed-executor-backend mp` 를 줘야 운영과 같은 멀티프로세스 실행기로 돎

- `pgrep -f` 를 `sh -c` 안에서 쓰면 자기 자신이 걸림

- 프로세스 이름이 바뀌는 앱은 `pkill -f` 가 안 먹힘 -&gt; PID 로

### 로그 회전 실패

- 엔트리포인트가 `/bin/bash` 를 지움 -&gt; `#!/bin/bash` 스크립트 실행 불가

- shebang 인터프리터가 없어도 에러는 "no such file or directory"

- `#!/bin/sh` 로 변경

### 근본 원인 추정: vLLM 버그 (#41530, #40926)

- PCIe, TP4, MTP 구성에서 같은 증상 보고. 수정 없음

- MTP 를 쓰면 0.30 에서 비동기 스케줄링이 로그 없이 자동으로 켜짐

- 완화: `--no-async-scheduling` (처리량 손해)

- 타임아웃 없이 영원히 멈추는 경우는 엔트리포인트로 못 잡음 -&gt; 바깥 헬스체크 필요

### 재현 = 같은 설정 + 같은 입력

- 멈출 때 처리 중 2건, KV 10%. 부하가 아니라 경합(race)

- random 벤치는 MTP 초안 적중률이 실제 요청(긴 JSON 출력)과 달라서 재현이 안 될 수 있음

- `vllm bench serve` 는 프롬프트를 미리 다 만들어 둠. 개수가 크면 준비만 한참 걸림

### nginx 단일 파일 마운트

- `sed -i` 는 파일을 바꿔치기함 -&gt; 컨테이너는 옛 파일을 계속 봄 -&gt; `cat > 원본` 으로 덮어쓰기

- 서버 빼기는 `down`, 반영은 `nginx -t` 후 `nginx -s reload`

## NPU

### SDK 0.12 변경점

- 칩 수 `--rbln-num-devices-per-local-rank`, 컴파일 설정 `--rbln-optimum-overrides`

- 컴파일 결과가 캐시에 남음. 길이·배치·칩 수가 바뀔 때만 재컴파일

### 임베딩·리랭커 한 칩 공유

- 두 서버 프로세스가 한 칩을 같이 씀. 동시 부하에도 에러 없음

- 칩 2개 -&gt; 1개

### 입력 모양 컴파일 시 고정

- 임베딩이 `[1, 8192]` 로 컴파일됨 -&gt; 짧은 입력도 8192 로 계산, 한 번에 하나씩

- 리랭커는 128토큰 단위 청크 계산이라 길이를 크게 잡아도 손해 없음

- 길이를 줄이면 빨라지지만 더 긴 입력은 에러

### 칩 수

- 챗(31B)은 8칩이 최소. TP 는 헤드 수로 나눠떨어져야 하고, 4칩은 KV 캐시 자리가 없음

- 칩을 많이 쓴다고 빨라지지 않음. 16칩 27B 가 8칩 31B 보다 느렸음

### vLLM 컴파일 vs 사전 컴파일

- 실행 속도는 같음. 차이는 기동 시간뿐 (사전 컴파일 쪽이 몇 배 빠름)

- 사전 컴파일: optimum-rbln `from_pretrained(export=True)` -&gt; `save_pretrained()` -&gt; 폴더를 vllm serve 에 넘김

- 컴파일만 해도 칩 종류를 읽어야 함 -&gt; 장치는 붙이고 `rbln_create_runtimes=False`
