### 개요

장비의 CPU·메모리·디스크·GPU 상태를 관리자 화면에서 보여 주는 기능

&nbsp;

### 문제

백엔드가 docker compose 컨테이너 안에서 돌고 있어서, 코드만으로는 장비 전체 상태를 읽을 수 없음.

> CPU·메모리: Java OperatingSystemMXBean은 컨테이너 기준 값을 줌  
> 디스크: 컨테이너에 마운트한 경로만 보임  
> GPU: 이미지에 드라이버가 없어 아예 못 읽음

백엔드 컨테이너에 호스트 권한이나 도커 소켓(컨테이너별 사용량)을 주는 방법도 있지만,  
수집·저장·보존 관리를 전부 직접 만들어야 하고 무엇보다 보안 문제가 클 것 같다고 생각

#### 그럼 어떻게 할까.

Grafana까지 붙이기: 화면은 우리 프론트가 그리니 Grafana는 필요 없음  
백엔드가 직접 수집하기: 시계열 저장을 DB 테이블로 다시 만들어야 해서 제외

-&gt; 수집은 exporter, 보관은 Prometheus, 백엔드는 조회만

&nbsp;

> 구성

**node-exporter**: CPU·메모리·디스크 측정

  - 호스트 루트를 읽기 전용으로(/:/host:ro,rslave)

  - rslave가 없으면 컨테이너가 뜬 뒤에 붙인 디스크가 안 보임

**dcgm-exporter**: GPU 측정

  - GPU 없는 장비에서는 기동에 실패 -&gt; compose 프로필로 분리

**prometheus**: 15초마다 수집해서 보관

  - 보존은 15일과 10GB 중 먼저 닿는 쪽에서 오래된 것부터 삭제  
     왜 15일&gt;&gt; 프로메테우스 기본값. 길 것 같은데.. 일단 해 보고 길다 싶으면 줄이기

&nbsp;

> API

**GET /current**: CPU·메모리·디스크·가속기의 현재값

**GET /history?metric=cpu&amp;range=1h**: 지표 하나의 기간 추이

&nbsp;

### 포인트

> PromQL을 받지 않음

화면은 지표 이름(cpu, disk 등)만 보내고, 조회식은 서버에 고정.  
관리자라도 임의 식을 넘기게 하면 무거운 식 하나로 Prometheus가 멈출 수 있음.

&nbsp;

> 기간과 상관없이 점은 240개

기간마다 점 간격을 고정해 둠. 1h는 15초, 6h는 90초, 24h는 6분, 7d는 42분.  
간격을 화면에 맡기면 "7일치를 15초 간격으로" 같은 요청(점 4만 개)이 들어올 수 있음.  
끝 시각도 간격 단위로 잘라서, 요청할 때마다 점 위치가 흔들리지 않게 함

&nbsp;

> 모니터링이 죽어도 관리자 화면은 살아 있게

Prometheus에 닿지 않으면 오류 대신 200으로 응답하고 available=false와 사유

&nbsp;

> 모르는 값은 0 말고 null

화면에서 "0%"와 "모름"을 구분

&nbsp;

> 가속기는 벤더와 상관없는 모양으로

NVIDIA와 NPU(리벨리온)는 exporter도 지표 이름도 다름  
응답은 사용률·메모리·온도·전력으로 통일하고, 벤더별 조회식만 서버 안에서 교체

가속기 종류는 자동 감지 말고 설정 -&gt; 자동 감지로 하면 exporter가 죽은 것과 가속기가 없는 것을 구분 불가

&nbsp;

> 실측하다 나온 것들

디스크 하나가 여러 경로로 잡힘  
-&gt; bind mount 때문, Docker Desktop에서는 한 장치가 경로 네 개로 나옴. 장치마다 제일 짧은 경로 하나만 남김

크기가 0인 가상 파일시스템(fuse 브리지 등)이 섞여 나옴. 디스크 목록에서 제외

장치 번호를 문자열로 정렬하면 10번 GPU가 2번 앞에 옴. 숫자로 비교해서 정렬

현재값 조회식이 10\~개라 하나씩 보내면 화면이 그만큼 늦게 뜸 -&gt; 순서는 지키면서 동시에(flatMapSequential)
