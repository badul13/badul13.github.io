###  NPU

신경망 연산(행렬 곱, 어텐션)만 빠르게 하도록 만든 칩

GPU 는 그래픽에서 출발한 범용 병렬 프로세서고, NPU 는 처음부터 AI 추론용으로 설계된 정도가 차이점

같은 일을 더 적은 전력으로 하는 게 목표 -&gt;&gt; 추론 서버에 많이 사용

###  GPU 와 같은 점

**드라이버 ↔ SDK 버전 짝**

- GPU: 호스트 드라이버 ↔ 컨테이너 CUDA

- NPU: 호스트 드라이버(KMD) ↔ 컨테이너 SDK. **짝을 필수로 맞춰줘야 함**

**컨테이너에 장치 넘기기**

- GPU: nvidia-container-toolkit + --gpus all

- NPU: CDI(Container Device Interface) + --device &lt;벤더&gt;/npu=&lt;번호&gt;

- CDI 설정 파일(/etc/cdi/\*.yaml)에 장치 파일·호스트 라이브러리·심볼릭 링크가 적혀 있음  
    --&gt;&gt; 이미지 안에 따로 넣을 필요가 없다

**서빙은 vLLM 그대로**

- 벤더가 vLLM 플러그인을 제공. OpenAI 호환 API 도 똑같아서 클라이언트 쪽은 주소만 바뀐다

### GPU 와 다른 점

**1. 모양을 컴파일할 때 고정**

제일 큰 차이. GPU 는 실행 중에 입력 길이·배치가 바뀌어도 그때그때 처리

NPU 는 모델을 미리 컴파일하면서 **최대 길이·동시 처리 수·쓸 칩 수**를 박아 넣음

- 바꾸려면 재컴파일, 대신 실행 경로가 정해져 있어서 빠르고 효율이 좋다

그래서 vLLM 인자와 컴파일 설정이 맞아야 함.

&nbsp;

**2. 장치 단위가 칩**

- 카드 1장에 칩이 여러 개(예: 4개) 들어 있고, 장치 번호는 칩 단위

- 큰 모델은 칩 여러 개에 텐서 병렬로 나누고, 작은 모델(임베딩·리랭커)은 칩 하나로도 가능

**3. 지원 모델이 정해져 있다**

- GPU 는 웬만한 모델이 그냥 돈다. NPU 는 벤더가 지원하는 구조(아키텍처)인지 먼저 확인

- 벤더 문서의 지원 목록·레시피 참조 필요

### 세팅 순서

1. **장치 확인** — 벤더 도구(rbln-smi 같은 것, GPU 의 nvidia-smi)로 칩 수·메모리·드라이버 버전 확인

2. **Docker + CDI** — CDI 설정이 있는지 보고, 컨테이너 안에서 장치가 보이는지 확인

>    docker run --rm --device &lt;벤더&gt;/npu=all ubuntu:22.04 &lt;벤더-smi&gt;

3. 추론 이미지 — 드라이버 버전에 맞는 SDK(컴파일러 + vLLM 플러그인)를 설치

4. 컴파일 + 서빙 — 길이·배치·칩 수를 정해서 컴파일하고 vllm serve로 띄우기

5.  /v1/chat/completions, /v1/embeddings 로 호출
